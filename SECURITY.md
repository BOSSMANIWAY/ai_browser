# Policy on Security Vulnerabilities

## Reporting a Vulnerability

Нашли уязвимость в AI Browser Agent (включая логику агента, веб-интерфейс
или обработку кредов)? Пожалуйста, **не открывайте публичный issue**.

Сообщите приватно через GitHub:

- **Security tab → Report a vulnerability**
  (https://github.com/BOSSMANIWAY/ai_browser/security/advisories/new)
  — приватный advisory, вы получите уведомление о статусе.

В отчёте по возможности укажите: версию/коммит, затронутый компонент,
шаги воспроизведения и потенциальный эффект. Мы подтверждаем получение
в течение нескольких рабочих дней и сообщаем о плане исправления.

## Scope

Проект выполняется локально и доверяет вашему браузеру и учётным данным —
это его модель работы, а не уязвимость. В scope:

- утечки секретов из репозитория или через API (`/api/providers`, WebSocket);
- выполнение произвольного кода на хосте через веб-интерфейс агента;
- обход `.gitignore`-гарантий для персональных данных (`user_profile.py`,
  cookie-файлы);
- сетевые атаки на встроенный сервер FastAPI (он должен слушать только
  `127.0.0.1`).

Out of scope: атаки, требующие физического доступа к машине или уже
скомпрометированного Chrome/аккаунта LLM-вендора.

## Our Practice

- Секреты (API-ключи, cookie сессий) читаются только из окружения и
  локальных файлов, перечисленных в `.gitignore`; в репозитории — лишь
  шаблоны `.env.example`.
- `/api/providers` отдаёт признак наличия ключа, но никогда — сам ключ.
- Веб-сервер по умолчанию слушает `127.0.0.1`; не выставляйте его в
  публичную сеть без собственного reverse-proxy с аутентификацией.
- Пароли и SMS-коды не сохраняются: только через `wait_user` в момент
  ввода.
